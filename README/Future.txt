1. Routing (مسیرها)

DRF → آدرس‌های API (/api/students/, /api/courses/)

Vue Router → آدرس‌های رابط کاربری (/dashboard, /courses/1)
📌 همپوشانی: هر دو چیزی به نام route دارن، ولی یکی مربوط به API، یکی مربوط به صفحات.

2. Validation (اعتبارسنجی داده‌ها)

DRF → Validation سمت سرور (امنیت + داده درست وارد DB بشه).

Vue → Validation سمت کاربر (مثلاً طول رمز کافی باشه یا ایمیل درست باشه).
📌 همپوشانی: هر دو می‌تونن validation کنن، ولی Vue برای تجربه کاربری، DRF برای امنیت.

3. State Management (مدیریت وضعیت)

DRF → دیتا در دیتابیس (منبع اصلی حقیقت = source of truth).

Vue (مثلاً Vuex یا Pinia) → نگهداری موقت داده‌ها در فرانت‌اند (state).
📌 همپوشانی: هر دو داده نگه می‌دارن، ولی DRF همیشه مرجع نهایی هست.

4. Authentication & Authorization

DRF → صدور و بررسی توکن (JWT یا Session).

Vue → نگه داشتن توکن در localStorage/cookie و ارسالش با هر درخواست.
📌 همپوشانی: هر دو درگیر لاگین هستن، ولی DRF امنیت رو کنترل می‌کنه، Vue فقط واسطه است.

5. Rendering

DRF → داده خام (JSON).

Vue → رندر کردن اون داده (HTML/Component).
📌 همپوشانی: هر دو می‌تونن داده رو “نمایش” بدن (مثلاً DRF Browsable API vs Vue Component)، ولی در عمل Vue مسئول UI هست.

6. Error Handling

DRF → کدهای وضعیت (400, 401, 403, 404, 500).

Vue → گرفتن اون خطاها و نشون دادن پیام مناسب به کاربر.
📌 همپوشانی: هر دو می‌گن خطا رخ داده، ولی DRF دلیل اصلی رو میگه، Vue باید قشنگ نمایش بده.

7. Business Logic

DRF → منطق اصلی (مثلاً محاسبه شهریه، سطح زبان، قوانین ثبت‌نام).

Vue → منطق UI (مثلاً اگر شهریه بیشتر از X بود، دکمه قرمز بشه).
📌 همپوشانی: بعضی وقتا هر دو نیاز دارن یک قانون مشابه بدونن، ولی DRF همیشه منبع اصلی قوانین.
